# 道具价值页

## 数据与维护

- 首页“资源获取”后的“资源价值”入口打开 `/gem-values`。
- Admin 维护道具名称、图标、一级多分类及钻石估值；Web 不保存第二份价格表。
- 浏览器打开页面时匿名、无缓存读取 Core 的 `GET /item-classifications` 和 `GET /items`。新增页面构建时不调用接口；保留 Next.js 静态导出。
- API 地址沿用 `NEXT_PUBLIC_CORE_API_URL`；未配置时沿用项目既有的本地/生产默认值。图片相对路径使用同一 Core 地址解析。
- 生产发布前确认 HTTPS API、图片路径及 Core 的 `CORS_ORIGINS` 包含 Web 的真实来源。生产环境连通性尚未验证。

## 展示规则

- 分类按钮及分组采用 Core 字典的名称、顺序和图标。“全部”按分类分组，未分类道具在末尾单独展示。
- 多分类道具可出现在不同分组；相同 ID 在每组中只出现一次，不根据图标去重不同品质道具。
- 每组按默认单价降序；没有默认方案时取最高方案价进行排序。所有估值方案均独立显示，不折算或累加；零价正常展示，未定价显示“未配置”并置后。
- 小数不按整数截断；中文名称直接使用后台名称，不展示参考站别名或审核状态。
- 大屏三列、中屏两列、手机一列。分类栏横向滚动、键盘可操作；每个分类按钮至少 44px 高。
- 请求失败显示中文错误并允许重试；图片失败保留名称和价格；不使用演示数据替代接口失败。

## 验证

- TypeScript 和本次新增、调整的 UI/数据模块相关 ESLint 通过。
- 旧 `lib/api.ts` 仍有 3 处既有 lint 错误；已将 Git HEAD 原文件与当前文件分别送入 ESLint 对比，错误内容完全一致，本次 API 地址函数抽取没有新增错误。
- 5 个相关测试文件共 14 项通过，覆盖首页入口顺序、首页状态、导航、分类、多分类去重、价格精度、零价、未定价、多个方案、错误重试、空状态、图片失败及重挂载重新读取价格。
- 调价传播通过模拟接口更新后的重新挂载验证；未修改正式价格或其他业务数据。
- 本地 Core 返回 145 项道具、123 项已定价；10 个分类名称均来自接口。149 个去重图标引用均返回有效图片，本地 CORS 允许 `http://localhost:3002`。
- 静态构建在独立副本中执行，保护源仓库现有 `.next`、`out`。
- 最终代码在 `/tmp/danke-web-gem-values-ic34ob1_` 构建成功，生成 244 个静态页面，用时 112.08 秒；其中部分既有攻略及图鉴页面超时后重试成功。新页面静态 HTML 包含加载外框，道具及价格由浏览器读取，不写入构建快照。新页面专属压缩 JS 约 16KB（不含共享依赖）。
- 开发站 `http://localhost:3002/gem-values` 实际 GET 返回 HTTP 200；静态输出同样包含 `/gem-values`。
- 浏览器工具报 `sandboxCwd is not a local file URI`，桌面及 320/375px 实机视觉、触控和实际浏览器网络检查仍待完成。
