# 资源获取玩家页实施与交付

## 已确认方案

默认按资源查，支持切换按玩法查。复用 Core 真实中文名称、一级多分类、图标和产出记录，卡片采用独立列瀑布流：桌面三列、平板两列、手机一列。默认展示三条，更多途径或奖励原位展开。保留当前录入数量，不折算每日/月度保底，不跨资源或重叠来源计算总收益。资源获取页不提供钻石价值跳转，独立价值页保留。

## 资源卡片合计（2026-11-03）

- 按用户要求，在“按资源查”的每张道具卡片中显示合计；汇总该道具的全部当前匹配途径，包含折叠隐藏项，展开/收起不改变合计。
- 搜索来源时仅统计匹配来源；搜索道具名称则显示该道具全部途径的合计。多分类道具在单个视图内仍只统计一次。
- 合计只代表当前录入数量的相加，不折算每日/月度保底，不把不同道具、箱子或碎片混合为一个类别总量。“按玩法查”不增加混合奖励合计。
- 小数显示精度跟随原始数量，消除常见浮点显示尾差，不统一截断为两位。
- 4 个相关测试文件共 15 项通过（4.69 秒），类型、相关 ESLint 和 diff 检查通过；覆盖折叠/展开一致、筛选联动及小数精度。
- 独立副本 `/tmp/danke-web-resource-totals-320x40jn` 静态构建通过（244 页、77.12 秒），未覆盖当前运行产物；本步未进行实机视觉验收。
- 此次只改 Web 的合计展示及相关测试，不改变接口、正式数量或数据库；回滚移除合计行及格式化函数即可。

## 数据规则与边界

- 复用 `/items`、`/item-classifications`、`/sources`、`/yields`，匿名无缓存读取，不请求 Admin，也不读取其他项目文件。
- 内部年月字段只用于选取最新完整快照，页面不标注为自然月收益。保留浮点数值，不合并来源，不根据来源类型推断单次/每日数量。
- 每条非零产出需关联真实道具和来源，异常响应失败重试，不以演示数据替代。相同记录 ID 去重，同一快照同一道具/来源出现冲突记录时停止展示并提示重试。
- 资源按钻石参考单价降序，未定价置后；玩法按中文名称排序。搜索道具或来源名称，条件只作用于当前可见关系集合。
- 未经审核的后台录入说明不直接公开；本次不新增获取条件或虚构玩法文案。

## 回滚

撤回本次资源获取页、新增适配及测试，恢复首页建设中标记。共享组件抽取及价值页链接支持可独立恢复，不影响已有价格、道具或产出。不执行数据库迁移或恢复操作。

## 独立列瀑布流调整（2026-11-03）

- 原普通网格按整行最高卡片排布下一行，短卡片下方留有大空隙。现改为资源获取专用 `AcquisitionColumns` 容器，不改首页的 `MasonryGrid`。
- 保留 640px / 1280px 断点，依次循环分列，每列内部独立纵向堆叠，间距 16px；展开不根据高度重新分配卡片，也不加入固定高度或空白占位。
- 展开状态提升至资源获取客户端，键为“视图＋稳定条目 ID”；窗口变化、分类搜索以及切换视图后，已展开条目仍能恢复。
- 删除资源获取页价值按钮、链接、分类参数计算及相关图标，不残留底部按钮间距。独立价值页、首页入口及资源价值降序排序保留。
- 验证：6 个相关测试文件共 21 项通过（5.82 秒），类型及本次文件 ESLint 通过；包含精确断点、一二三列分配、不重不漏、展开状态保留和首页瀑布流回归。
- 独立副本 `/tmp/danke-web-acquisition-columns-a8xqzgd_` 静态构建通过（244 页、64.44 秒），源仓库运行产物未执行构建覆盖；本地 `/yields` GET 返回 HTTP 200。
